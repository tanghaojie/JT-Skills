# 看盘与复盘资料的 Skill 拆分评估

> 历史方案，已由用户后续决定取代。2026-10-22 用户指定实现两个 Skill：[jt-stock-review](../../skills/finance/jt-stock-review/SKILL.md) 与 [jt-stock-intraday](../../skills/finance/jt-stock-intraday/SKILL.md)，均按大盘、板块、个股分析。盘前准备并入盘中 Skill，个股强弱纳入两者，交易执行复盘作为盘后 Skill 的有条件环节。下文保留初始五项候选评估及当时的未实施状态，不作为当前索引。

评估日期：2026-10-22。依据：[原始材料](2026-10-22-market-review-original.md)、[内容核对](2026-10-22-market-review-verification.md)及仓库“一项重复任务对应一项交付结果”的约定。

## 建议：5 个候选 Skill

按任务目标与交付物拆分为 5 个，而不是把十二个章节各做一个 Skill。原文的量价、量比、资金流和分时形态主要是分析方法；“进阶路径”尚没有可执行的诊断标准。本次只建立候选方案，不创建或登记可调用 Skill。

| 候选名称 | 使用时机与必要输入 | 核心交付物 | 对应原文 | 明确边界 |
| --- | --- | --- | --- | --- |
| `jt-a-share-premarket` | 用户要求盘前准备；交易日、数据截止时间、市场、持仓或自选（没有则仅做市场准备）、官方公告与事件资料、已有交易计划 | 盘前清单：隔夜背景、公告事实、待关注事件、事前预期与可观察触发／失效条件、数据缺口 | 二；三的事前观察项目；十一第四步 | 不预测开盘必涨必跌；不把新闻标题直接认定为利好利空；缺少个人风险参数时不擅定仓位与止损金额 |
| `jt-a-share-intraday` | 用户要求竞价或盘中观察；指定时点及同口径的指数、市场宽度、板块、竞价／分时数据；平台图例 | 盘中快照或对比记录：市场变化、候选板块、与盘前预期的偏差、需继续观察的证据 | 三、四的市场部分、五；一、八作为方法 | 只评价截至当前已知信息；无实时工具则分析用户提供的时间戳快照并注明时效；一次调用不等于持续盯盘或自动提醒 |
| `jt-stock-strength-review` | 用户要求评估指定个股；证券代码、观察周期、可比基准、价格成交序列、复权方式、均价／量比定义 | 个股证据卡：相对收益、价量描述、位置与形态、支持及反对解释、失效条件和缺失项 | 四的个股部分、六、七、九、十；八作为口径约束 | 不用大盘结论替代个股证据；不凭形态识别主力身份或动机；不自动生成“必买”结论 |

`jt-trade-review` 名称保留一般性，因为执行复盘方法可跨市场复用；本批材料只支持 A 股背景。将来要支持其他市场，必须增加对应交易规则与成本处理，不能仅改名称或描述就宣称覆盖。

## 为什么不拆更多

- **集合竞价／开盘半小时／后续盘中观察**：共享同一份当日观察记录，适合作为盘中 Skill 的时间阶段，不必独立维护三套入口。
- **主线识别／板块轮动**：是盘中观察和收盘复盘的分析项。先明确两个任务的截止时点与数据范围，不另做含混的“主线选股”。
- **量价／量比／分时形态／资金流**：目前没有独立且不同的交付物，作为个股证据卡的方法及必要定义。需要时放在该 Skill 的 references，其他 Skill 只使用各自必需的简短定义，不引入强制串联调用。
- **情绪判断／个人心态复盘**：前者描述市场，后者需要用户记录，分别属于盘中／市场复盘与交易复盘，不能合并为读心式“情绪判断”。
- **交易进阶／学习规划**：原文只有目标与泛化建议，缺少能力测评、练习、反馈周期和验收结果，本批不够支撑独立 Skill。
- **金融资料核验**：本次确实执行了核验，但单份资料不足以确定新 Skill 的重复输入与独特工作流。先积累案例，不为已有章节数或目录完整度额外创建入口。

## 实现时必须吸收的修正

1. **先检查数据可用性。** 标明交易日、时间、时区、品种、数据来源、单位与延迟；用户提供的快照可直接使用。需要实时数据而没有工具时，列出缺口，不能补造行情或自称已经监控。
2. **分开记录观察、解释与建议。** “成交额增加”是观察，“关注度可能提高”是解释，“达到用户既定触发条件”是对照结果；“主力正在洗盘”没有身份数据就不能当事实。
3. **按实际软件确认指标。** 使用正确的单位时间量比；区分成交量、成交额、换手率；黄白线和个股均价线须读图例。资金流仅按供应商口径解释，不能与账户净入金或投资者身份混用。
4. **不用未经验证的口诀作硬规则。** 3 只涨停、连续 3 天、2%—4% 高低开、量比 2／5 等仅是原作者举例，不自动成为参数默认值。没有样本验证，不输出胜率或稳定盈利结论。
5. **限定数据时间。** 盘前不读盘后信息；盘中不偷看收盘结果；交易复盘区分事前可知和事后得知。季末机构持仓不能当作当日同步买入证据。
6. **计划与执行分别判断。** 纳入可卖数量、普通 A 股当日新买入的卖出限制、费用、滑点、停牌或无法成交的情形。没有用户事前计划就只做记录与缺口整理，不补造计划。

这些是本次候选设计的约束，不是用户既有交易系统、风险偏好或操作习惯的声明。后续实际 Skill 应自包含，不强制依赖本仓库 inbox 才能运行；保存原始来源的链接只承担溯源作用。

## 建议落地顺序

优先做 `jt-a-share-market-review` 与 `jt-trade-review`：交付结果相对明确，可使用完整收盘数据或日志验收；二者分别回答“市场发生了什么”和“自己的执行有什么问题”。其次做盘前准备、个股强弱评估，最后做依赖及时行情和多时点对照的盘中观察。此顺序是实现建议，不代表已经获得任何行情工具或个人交易记录。

## 后续行为验收场景

| 场景 | 应观察到的行为 |
| --- | --- |
| 输入 9:23 的竞价截图和拟匹配量 | 指明未到最终撮合结果，不将拟匹配量当成全部已成交，不使用 9:30 后的数据 |
| 同板块只有 3 只涨停，其余普遍下跌 | 记录聚集现象与市场宽度反证，不自动判定“最强主线” |
| 两软件的主力净流入方向相反 | 先检查口径和时间范围，无法对齐则并列记录，不按叙事偏好挑数据 |
| 只给当前累计成交量与过去 5 日平均日成交量 | 识别缺少已交易分钟等信息，不能直接算出分时量比 |
| 个股慢涨缩量但缺少持股与委托身份数据 | 可描述价量，不能断言主力控盘 |
| 一笔赚钱交易违反事前计划，另一笔合规交易亏损 | 分开评价结果和执行；不按盈亏反推纪律好坏 |
| 没有事前计划，要求评价“按系统执行得如何” | 明确不可评价的部分，允许分析成交和成本，不补写事前计划 |
| 用季度北向持仓与当日软件资金流要求判断同步加仓 | 指出时间与身份口径不一致，结论保持未确认 |
| 模拟上午新买 A 股、下午跌破止损价 | 核对可卖数量，不把当天新买部分模拟为可即时卖出 |
