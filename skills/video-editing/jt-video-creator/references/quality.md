# 验收与交付

按实际内容选择检查，不因有命令输出就宣称视听通过。

| 范围 | 验证方法 | 失败时处理 |
| --- | --- | --- |
| 随机访问 | 用独立浏览器或独立渲染会话按不同顺序绘制同一时间点，比较图像 | 去掉累积状态、实时钟和不稳定加载 |
| 画面 | 每 1–2 秒联系表；关键动作按约 0.2 秒间隔放大；检查开场、结尾和切点前后 | 修复空帧、遮挡、穿插、主体过小、过暗或颜色混淆 |
| 文字 | `readcheck.mjs` 加最终尺寸人工看字；字幕起止、字体缺字、边界与安全区检查 | 重排、精简或延长；空 TEXTS 不是通过证据 |
| 声音 | 逐句 ASR、必要听音；最终混音再核对，测 ebur128 与真峰值 | 改错读、截断、音量和遮蔽；记录 ASR 例外 |
| 音画节奏 | 画面事件与音乐、拟音、字幕来自同一时间轴，检查关键点时间差 | 回到时间真源调整，避免各轨分别补丁 |
| 技术参数 | ffprobe 检查视频/音频流、尺寸、fps、时长、编码；ffmpeg 全文件解码与 blackdetect | 黑场先对照预设留白，不把所有黑场判错 |
| 来源与独立创作 | CREDITS、FACTS、素材登记；对比 demo 的结构与联系表 | 删除误带的示例品牌、故事、角色、片尾和未核实事实 |
| 可重建 | 从工程外部运行交付的构建命令，输出到新目录 | 修正硬编码、漏资源和环境说明，不覆盖唯一成片 |

常用最终文件检查，先替换成当前工程实际路径；Windows 路径按当前 shell 引号规则处理：

```text
ffprobe -v error -show_streams -show_format -of json film.mp4
ffmpeg -v error -i film.mp4 -f null -
ffmpeg -i film.mp4 -af ebur128=peak=true -f null -
ffmpeg -i film.mp4 -vf blackdetect=d=0.1:pix_th=0.10 -an -f null -
```

最后以正常速度带声音看一遍，并检查结尾。当前环境只能看静帧、做技术检查或读 ASR 时，将完整视听验收列为未完成。检查不通过的成片不能标“已验收”；保留实际结果和原因。

修复一批有证据的问题后再核验；因修改引入的问题继续处理。无新证据或无进展的同类重试最多两次；超出资源预算或必须变更用户规格时报告选项。用户后续意见作为新的修改范围。

交付至少包含：MP4、海报、适用的 SRT、创作方案、源代码与必要素材、一条重建命令、CREDITS；有事实内容时包含 FACTS 和素材登记。构建说明记录工具库绝对路径/可配置变量、固定 commit、依赖版本、字体和模型位置。缓存、虚拟环境和逐帧中间件可以不打包，但不可漏掉不可再获取的必要原料。

不得自行把 LemoLab、JT 或模型名称绘制成用户成片的水印或背书。复制的 MIT 代码保留许可证与 CREDITS 中的署名；这不要求片尾出现品牌。
