# 制作规范

## 一条时间轴

用项目中的 `timeline.json` 或 `timeline.js` 作为时间真源，记录分段、镜头、tempo、节拍、动作事件、旁白起止、字幕和留白。配乐、混音、画面与 `.srt` 读取同一组数值。录音实际时长改变时，调整此处，再重建下游；不要分别手调四份时间表。

## 可随机访问的画面

页面约定来自固定版本上游工具：

```js
window.DUR = 8; // 示例时长；由当前项目时间轴计算
window.render = async (t) => { /* 完整绘制 t 秒的画面 */ };
window.EV = [{ t: 1.5, type: 'impact' }]; // 供声音与节拍核验
window.TEXTS = (t) => []; // 可见文字的 id、完整 text、x0/y0/x1/y1
// 在字体、图片及必要资源全部就绪后才设置：
window.READY = true;
```

`render(t)` 应能在任何顺序调用，相同 t 得到相同画面；不用实时钟、未设种子的随机数或上一帧累积状态。粒子、骨骼、进度与噪声按 t 和固定 seed 求值。异步图片、视频 seek 或解码必须等待完成；不能先返回再补画，使截图拿到上一帧。

`TEXTS(t)` 从文字第一次可见起报告完整文本和真实包围盒；打字机不能只报告已打出的几个字。字幕另外按字幕时间轴检查；没有屏幕文字时明确标为不适用，不能用空数组掩盖未接入的检查。

页面从 `/core/...` 和 `/node_modules/...` 引用工具库；项目位于 `/@film/`，项目资源使用相对路径。不要把上游 demo 的 `../..` 当作当前项目路径。画幅取 `innerWidth/innerHeight`；每个工具调用都传一致的 `--size`，视频与封装使用一致的 fps。风格需要隔帧动作时，只让角色按较低帧率步进，摄影机和光线保持输出帧率。

## 中文配音与字幕

1. 用户录音或指定声音优先。无此输入时，联网且允许向该服务发送文案的项目可用 `core/tts/tts_zh.py`（edge-tts）；离线可用已备好的 Kokoro 中文模型和中文声音，或用户录音。先说明声音选择，不能在网络失败时悄悄换声音。
2. `lines.json` 的基本字段为 `id`、`text`；edge-tts 可以加 `say`、`voice`、`rate`、`pitch`。`text` 保留屏幕写法，`say` 写实际读法，例如数字、单位、多音字。Kokoro 使用 `lang: "cmn"` 与其支持的中文 voice；字段按对应脚本区分。
3. 逐句生成 WAV 后记录真实时长，做 ASR 核对并听取有疑问的句子。只有确实听过并确认发音正确，才把识别器的同音字写进 `asr` 例外字段；记录理由。不得修改参考文本来掩盖漏字、错读或根本未听音。
4. 中文字体必须覆盖影片全部字形。上游 `core/fonts/` 的中文子集只有约 200 字，不足以支持任意中文稿。使用本地合法字体或按本片文字准备并自托管字体子集；保存字体来源与许可，渲染期间不依赖远程字体加载。
5. 字幕与画面文案分开管理。普通字幕起点为每条至少 1.8 秒，并给口播结束留约 0.6 秒；长句应拆分。画面文字按“中文字符数 ÷ 4.5 + 其他非空字符数 ÷ 15 + 1.5 秒”估算阅读时间，随后结合实际画面检查。不能为满足时长而压成观众读不完的小字。
6. `.srt` 来自同一字幕 cues；烧录字幕的颜色、位置和动画适配风格。竖屏重排安全区，不能直接裁掉横屏两侧。

## 音乐、拟音与混音

先有节拍图，再做动作对齐。用户音乐优先；否则可用采样器、拨弦物理建模或程序合成。采样器不等于音色库已经安装，只下载当前用到的库。`core/audio/INSTRUMENTS.md` 记录各库许可；使用 `credits()` 返回值生成相应署名。

重要拟音来自动作事件；环境底、音乐、旁白分轨保留。先压缩旁白的动态，再按听感和测量平衡，旁白比音乐高约 8–10 dB 是起点而非通用验收值。检查低频是否遮蔽人声、小扬声器是否仍清楚。默认母带目标约 −14 LUFS、真峰值不高于 −1.2 dBTP；平台或用户另有要求时使用其标准。静音片不强行套响度指标。

上游 `mux.sh` 做两遍 loudnorm、音频补齐或截断与封装；像素、矢量风格 grain 为 0。Windows 原生可用项目自己的 Python/PowerShell 包装相同 ffmpeg 步骤，先试运行，不假定 shell 脚本兼容。

## 真实素材与事实

实证和纪实影片先确认资料能支持什么，再决定镜头。为每个素材保留源页面、作者、下载日期、适用许可、文件名、使用片段；在 `FACTS.md` 逐条写主张、来源、必要短引文或计算过程、单位、时点、限制。`CREDITS.md` 管署名，不能代替事实证据。

数据缺失、历史照片、示意画面、外地素材和测量误差必须按实际标注。不得把插画当原始影像、把季度损失相加说成年净损失、把推算说成来源原话。档案视频先抽取当前片段所需的确定性帧序列，保留原始时间码。

优先用户有权使用的素材、明确的公有领域作品、CC0、CC BY 与 OFL 字体。逐项记录实际许可；公有领域不等于 CC0，网站可访问或“无已知限制”不等于已核实许可。其他许可依项目使用方式核对条件；有需用户接受的额外条件才集中询问。上游 MIT 仅覆盖相应代码和文档，不替代外部影音、字体、数据的许可。
