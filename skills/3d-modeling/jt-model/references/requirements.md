# 需求表与缺项处理

在正式建模前使用本表。先从当前指令和项目文档提取答案，仅询问仍缺失且影响验收的项。表格是检查维度，不要求每次把整张空表发给用户。

## 要核实什么

| 维度 | 需要明确的内容 | 何时需要询问 |
| --- | --- | --- |
| 目标与用途 | 对象、制作或修改、现有资产路径、写实／风格化、作品展示／实时引擎／制造等验收用途 | 对象或用途不明；“精细”没有可依赖的项目质量标准 |
| 工具与项目 | 首选 Blender；项目要求的版本、插件、脚本入口、输出位置 | 项目位置不明、工具冲突或缺少必要能力；不要仅因未锁定次版本就阻塞 |
| 尺度与结构 | 单位、主体尺寸依据、原点／朝向、可见细节、内部结构是否需要 | 尺度会影响建模或导出；不能把推测的内部结构当实测 |
| 周边环境 | 需要／不需要／未明确；若需要，中心、范围数值和单位、半径／直径／方形边长或地理边界、真实还原还是概念环境、精度范围 | 单独的“周边 2000 米”未说明几何含义；不能直接推断半径 |
| 动画与动效 | 需要／不需要；装配、拆解、运镜等类型；先后顺序、运动方向、组装高度、落地过程、时长、循环、交互或视频 | “飞入组装”不等于已指定高空组装再落地；关键动作缺失时询问。FPS 等可由既有规范或已授权的技术决策决定 |
| 资料来源 | 用户素材／自主检索、可信照片和图纸、是否需要精确尺寸或测绘、参考图本地保存位置、使用与发布权限 | 来源不可得、证据冲突或期望精度无法支撑；不得用生成图冒充实景或可靠图纸 |
| 材质 | PBR／风格化、贴图来源与许可、UV、玻璃与金属等关键表面、目标引擎支持范围 | 没有视觉标准且选择会显著改变结果 |
| 光线与昼夜 | 需要的时段、静态效果图或动态昼夜、太阳／环境光责任在资产还是宿主、夜景窗灯／发光策略 | 文档未说明，或用户说“按规范”但规范缺失；四张静态图不能替代动态昼夜验收 |
| 渲染 | 引擎、设备可用性、镜头和构图、图片／视频、画幅与分辨率、质量和时间约束 | 没有渲染用途或成果标准；可先提出小图预览与最终输出的建议 |
| 导出与性能 | 源工程、目标格式／宿主、坐标轴／单位、动画兼容、面数／体积／纹理预算、LOD（如需要） | 目标软件契约不明；三维打印／BIM 不得沿用网页可视化验收标准 |
| 发布与验收 | 仅本地或需提交／推送／部署、仓库和分支、平台／环境、验收方法 | 本次未授权外部操作，或目标不明；项目写了发布教程不代表本次要求发布 |

每项记录值、状态、依据；依据至少能定位到当前用户消息或项目文档路径和章节。技术参数只有在可由标准推导、影响较小或用户明确委托时才自行决定，并在任务说明中注明。不要把本次参数追加成跨项目的永久偏好。

## 不同缺项的处理

**已有规范且本次要求充分**：例如用户说“不需要周边；材质灯光按当前项目规范；只交本地 GLB”。将街区和发布标为不适用，读取实际规范并检查工具后开始。不要继续询问街区距离、发布平台或已由文档决定的灯光。

**没有规范**：先归纳已知要求，给任务说明草案并询问真正缺失项。可以这样合并提问：

> 当前项目未找到有效建模规范。已知要做写实主体模型，以下三项会影响交付：① 是否需要周边；若需要，请给范围及半径／直径等含义；② 是否需要装配动画及关键动作；③ 本地导出还是发布，以及目标格式。你答复后，我会把已知要求与答复写成此次任务说明。

问题必须随已知条件删减；本次已明确格式、范围或动作时，不照抄示例继续问。若用户已明确授权新建说明并给全要求，可直接写入，无需额外确认。

**规范冲突**：列出双方依据与影响，例如“用户要保留透射玻璃，但目标格式规范禁止该扩展”。提出可行选项，在解决前停住相关导出；不改写项目标准来掩盖冲突。

**工具缺失**：区分“未在 PATH 找到”“已找到但版本命令失败”“MCP 未连接”“试渲染失败”。只有完成适当候选路径与替代路径检查后，才得出当前阶段不可执行的结论。给出让用户指定现有路径、连接工具或另行授权安装的选项。

## 恢复工作

收到答复、连接恢复或新文档后，只更新受影响项并补做必要检查。保留先前证据和源工程，不重复问已回答的问题。未经答复的必要选择继续保持缺失状态；草案不等于确认。
