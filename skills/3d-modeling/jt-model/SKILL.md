# JT 三维建模

把三维建模请求转成有依据、可复现、可验收的资产。以 Blender 为首选执行路径；本次用户或项目明确选择其他工具时按其执行。不要把参考案例的街区范围、动画参数、模型标准或发布平台当成所有任务的默认值。

## 开始前：先找已有要求

1. 确定当前项目根目录与本次目标。遵循适用的 `AGENTS.md`，先读根 README 和文档索引，再定向查找建模规范、资产契约、任务说明、渲染配置、导出规则和发布说明。仓库有 CodeGraph 且项目要求使用时，先按其规则查询代码。
2. 按索引追踪当前生效文档，不遍读整个仓库。文件名未知时，可用 `rg --files` 查找 `docs/`、`specs/`、`models/` 等实际存在的路径，再搜索 `建模|街区|材质|昼夜|装配|导出|Blender|model|render|animation|publish`。不要扫描凭据、依赖目录或二进制模型。
3. 区分长期规范、当前资产任务说明、旧模型案例和归档。只复用适用于本次目标的内容；旧模型的 2000 米范围或 36 秒动画不构成本次要求。用户已明确的新选择优先；若与必须满足的导出契约冲突，提出具体冲突和可选解决方式，停住受影响部分。
4. 读取 [requirements.md](references/requirements.md)，把本次指令与有效文档合并成需求表。每项记录值、状态（已明确／缺失／冲突／不适用）和依据（用户原话或文档路径及章节）。找到了文件不等于其中已经写全要求。

已有要求完整时，简要说明复用依据并直接执行，不要求用户重新确认一遍。不把旧会话的外部操作授权带入新任务。

## 同时核实可用工具

先通过当前宿主实际提供的工具列表发现 Blender/MCP、终端、浏览检索、文件与图片查看能力。不要仅凭工具名字、已安装插件或旧会话推断连接可用。

有 Python 和终端时，可运行随 Skill 分发的只读探测脚本；将下列路径替换为当前 Skill 的实际位置：

```text
python /path/to/jt-model/scripts/probe_tools.py
python /path/to/jt-model/scripts/probe_tools.py --blender "/path/to/blender" --require blender
```

脚本仅检查 CLI 候选路径和版本，输出 JSON；不会连接 MCP、安装软件、修改场景或验证渲染。不指定 `--require` 时只做盘点，退出码 0 不代表全部工具可用；指定的 CLI 缺失或失败时返回 2，仍需独立判断 MCP 路径。没有 Python 时，用宿主工具或系统命令完成同等检查，不为运行探测脚本强制安装 Python。`ffmpeg`、`git` 只是条件能力，不是所有建模任务的前置依赖。

| 当前阶段 | 应核实的执行能力 |
| --- | --- |
| 建模 | Blender CLI 版本可运行，或 MCP 能执行只读版本／场景查询；指定其他 DCC 时核实等价能力 |
| 参考研究 | 能检索并读取来源；需要本地参考图时还能保存和查看文件 |
| 材质与渲染 | 在临时输出中做低成本小图试渲染，记录实际引擎与设备；版本成功不等于 GPU 可用 |
| 动画与导出 | 当前工具能导出所需格式、保留动画／材质，并有适合该格式的验证或回读路径 |
| 视频与发布 | 按交付需要探测编码器、仓库工具、目标平台、凭据可用状态和部署查询能力；不输出凭据 |

连接已有 Blender 场景时先读取状态，保护未保存工作，不重置或覆盖当前工程。项目脚本先看用途与副作用再运行。MCP 不可用而 CLI 可用时，可以在同一授权范围内切换路径并说明；替换用户指定软件、降低必要效果、安装插件或产生费用不能悄悄进行。

## 缺项时怎样询问或停止

- **没有有效规范或任务文档**：说明查过哪些入口，整理已有用户要求，合并询问缺失项以及是否将本次答复作为任务说明。可先给可审阅的任务说明草案；在用户答复或已有明确授权允许建立该说明前，不进入正式建模。用户指定了找不到的文档时，不编造其内容。
- **文档存在但关键项缺失或冲突**：只问影响范围、外观、时间成本或验收的缺项。附适合本次任务的建议值供选择，建议仍是未确认值；不靠超时或沉默表示同意。用户已说“其余你决定”时，可在其范围内决策并记录依据。
- **必要工具不可用**：报告尝试的路径、实际错误、受阻阶段和恢复方式，停止该阶段。不把一份尚未在 Blender 运行的生成脚本称为已完成模型。不自动下载软件、改全局配置、付费或绕过访问限制。
- **仅可选阶段受阻**：继续不依赖它且已获授权的工作，清楚标记未完成项。例如只有发布凭据缺失，可以完成本地资产；没有渲染工具时不能宣称画面验收通过。
- **无法交互**：输出一个简短的阻塞清单和可恢复的下一步，停止依赖缺项的操作。相同错误没有新证据时不反复重试。

询问时优先用宿主的用户输入工具，缺少该工具时直接提问。把相关问题合并，已确定“不需要”的街区、动画或发布标为不适用，不继续追问细节。

## 执行与交付

需求和对应阶段的工具就绪后，沿用项目现有任务说明和目录。需要新说明时，在项目约定位置记录需求表、来源、工具检查、交付项与未解决项；小改动只追加与本次变更有关的信息，不重建整套档案。

按当前任务的分支阅读 [delivery.md](references/delivery.md)：资料与建模部分适用于资产制作；只有需要街区、动画、渲染或发布时才执行对应部分。先用低成本体块、关键视角或阶段帧核对比例与动作，再投入高精度几何和最终渲染。只有用户或项目要求审核节点时才停下等审核。

完成时报告资产与源工程位置、已执行检查及证据、估算和未验证范围。已授权发布时继续到对应的远程验证，不在“已推送”处宣称发布完成；未授权发布时交付本地成果，不自动推送或上传。Skill 自身的调用不授予安装、发布或其他外部操作权限。
